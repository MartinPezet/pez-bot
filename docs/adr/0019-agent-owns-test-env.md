# The agent adds its own test env through a branch file

Project config is read only from the default branch so agent edits can't change the gates, the allowed authors or the tool rules. That also locked `extraTestEnv`, so a change that added an env var the app validates at boot (earth-scope #74, Stripe keys) could never pass its gates: the fix agent couldn't add the dummy value, burned every fix attempt, and blocked until the owner hand-edited config. Now the agent keeps dummy values in a committed `.backlog-runner.env` on its branch, which the runner reads from the worktree for installs, gates and Claude's own environment. It can only add names: `extraTestEnv`, the test-service variables and the runner's own variables always win, tool-changing names (`PATH`, `NODE_OPTIONS`, `LD_*`, `GIT_*`, `npm_config_*`, Claude auth…) are refused, and values that look like credentials are refused; any refused entry fails the gates so the fix agent sees it. This grants nothing new, because the agent already writes the code the gates run, and every entry shows in the PR diff. Gates, authors, tools and prompts stay default-branch-only. Production values stay the owner's job, flagged under "Production config needed" in the PR body; GitHub Actions sees the file only if the target repo's workflow loads it. With the App's Workflows permission the agent adds that one load step itself; prompts forbid any other workflow edit, but nothing enforces it, so workflow changes in bot PRs need owner review.

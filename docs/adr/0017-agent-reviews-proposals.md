# An agent reviews proposals instead of the owner

Every proposal used to open its own PR, and the owner merged it to approve the build. That review step cost the owner a context switch per item for a document that mostly restated the issue. Now a second Claude call with a fresh context checks the proposal against the issue and its trusted comments, the writer revises from its gaps (up to `maxFixAttempts` times), and a pass approves the item. The spec is pushed to `change/issue-N` and reaches the owner inside the implementation PR, which stays the only human approval. The trade-off is that a misread issue is caught later, after the code is written, rather than before. Review feedback on the implementation PR (and blocking on gaps the reviewer can't settle) limits that cost, and it saves a round trip on every item. An unreadable verdict blocks rather than passing, so unreviewed proposals are never built.

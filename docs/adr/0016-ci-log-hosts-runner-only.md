# CI log hosts are open to the runner user only

Automatic CI fixes need the failed job's log, and GitHub redirects `/actions/jobs/{id}/logs` to `productionresultssaN.blob.core.windows.net`, numbered hosts with no published list, on Azure storage addresses shared with other accounts. Annotations stay on `api.github.com` but often say only `Process completed with exit code 1`, and adding the hosts to the main allowlist would let agent-run code send data to any storage account on those addresses. So these hosts get their own ipset, re-resolved with the main one and matched by `--uid-owner runner`, which extends ADR-0014 using the split from ADR-0002: the runner downloads the log and hands the agent text, and the agent stays default-deny (start-up verification fails if the agent user can reach them). The runner is trusted to reach these addresses because it never runs agent code. If the rule or the hosts are missing, the only cost is unreadable logs, so failed PRs block.

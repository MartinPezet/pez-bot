# Usage gauge: passive events plus a Haiku probe, unknown allowed

There is no official headless usage API on Pro. The gauge records `rate_limit_event`s from every stream-json run and, when no reading is fresh, makes a one-turn Haiku call to get one. Rejected: the undocumented `/api/oauth/usage` endpoint and `anthropic-ratelimit-unified-*` headers (aggressive 429s, OAuth token used outside Claude Code), and `claude -p "/usage"` (tested 2026-10-07: headless it prints only session cost, not plan limits). Readings are therefore often unknown, so `USAGE_UNKNOWN_POLICY` defaults to `allow` with a digest warning per occurrence; passive `allowed_warning`/`rejected` handling is the safety net. The gauge interface mirrors the status-line `rate_limits` JSON, the likeliest future official source.

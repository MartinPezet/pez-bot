# The daemon serves the web UI, behind a password and a firewall rule

ADR-0015 kept the UI on the host so nothing listened in the container, but the owner's server has no Node or npm, only Docker, and wants the page there. A separate UI container would need the Docker socket to reach the runner, which is root on the host and which the runner setup forbids; a second copy of the image would run agent code beside the server and solve nothing. So the daemon serves the page itself on port 8377 when `UI_TOKEN` is set, and runs the CLI as child processes. This gives up "nothing listens in the container", which costs two controls: HTTP Basic auth with a token the agent can't read (it sits in the runner's environment, and agent commands get `env -i`), and a firewall rule matching `--uid-owner agent` that rejects the agent user from the port ahead of the loopback accept, extending ADR-0002 and ADR-0016. If that rule can't be added, the firewall check fails and Claude jobs are refused. Auth is the control that always applies, because sidecars can still reach the port and agent code can drive the test Postgres. The page is plain HTTP, so it's published on `127.0.0.1` and reached by SSH tunnel. The UI is off without a token, which keeps the old security model for anyone who doesn't want it.
